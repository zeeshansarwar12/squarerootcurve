# SEO

## Domain and targeting

- Canonical domain: `https://squarerootcurve.com/`
- Preferred host: non-`www`, HTTPS only
- Primary homepage keyword: `square root curve`
- Secondary homepage terms: `square root curve calculator`, `square root curve chart`

Use related terminology only when genuinely relevant; do not keyword-stuff.

SEMrush US snapshot supplied for the project (directional estimates, not ground truth):

- square root curve — 12,100 volume / KD 13
- square root curve chart — 2,400 / KD 30
- square root curve calculator — 1,900 / KD 15
- grade curve calculator — 2,400 / KD 8

## Strategy

The observed main-keyword results are fragmented across PDFs/reference documents, Reddit, YouTube, and formula/explanation pages. Build a superior canonical resource that combines calculation, lookup, chart, print, download, formula, and explanation on one flagship page—not merely another calculator.

Put the tool and result first; do not place 1,500 words before them. Follow with concise explanatory content.

Working title direction:

`Square Root Curve Calculator & Chart | SquareRootCurve.com`

Keep it near normal search-result length and do not mechanically rewrite it. H1 direction: `Square Root Curve Calculator`. Use “square root curve” naturally near the top.

## Site architecture

Only after the flagship page is strong, consider:

- `/grade-curve-calculator/`
- `/bell-curve-grade-calculator/`
- A genuinely useful guide to grading on a curve when intent justifies it

Do not create thin keyword variants or programmatic score pages such as `/square-root-curve-64/`; the full lookup table belongs on the homepage.

## Indexing, schema, and links

Every indexable page needs a unique purpose. Do not index utility-state URLs; calculator query parameters must not create duplicate indexed pages.

Before adding structured data, verify current Google-supported documentation, describe only visible content accurately, and validate the output. Do not assume a calculator schema earns a rich result. FAQ content may serve users without promising FAQ rich-result eligibility.

Use descriptive, natural internal-link anchors without aggressive exact-match repetition. The exact topical brand makes artificial keyword-rich anchors unnecessary.

Accuracy and usefulness take priority over page count. Build a specialist resource, not a generic calculator network.
