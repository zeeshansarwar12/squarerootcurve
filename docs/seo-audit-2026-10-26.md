## Findings and proposed fixes

1. **Existing equivalent reference (high priority).** The chart route already server-renders every score 0–100 using `generateSquareRootCurveChart()` and `formatCurveValue()`. The homepage also includes the full chart. Creating `/square-root-curve-table/` would repeat the same primary intent. Enhance the existing chart route, preserve its canonical and print layout, and add the requested table heading, selector, filtering, score examples and FAQs there. No new route or redirect is warranted.
2. **Score intent gap (high priority).** Chart page has no interactive lookup, filtering, or score-specific examples. Add visible, server-rendered examples for 66, 72, 77 and 86 using shared calculations, with one-decimal display rounding. Do not create score URLs.
3. **Internal links (medium).** Homepage links to both supporting routes; chart links back to homepage calculator/formula; comparison links to chart and homepage. Add contextual links directly to the enhanced table and links back to chart/print and comparison tools. Use normal HTML anchors.
4. **Content accuracy (medium).** Homepage claims lower scores always get a larger absolute boost and graph caption includes zero as above the reference. Boost actually peaks at 25 (25 → 50); 0 and 100 both gain zero. Correct these statements and the corresponding calculation documentation. Core math is already correct and must stay unchanged.
5. **Indexability (low).** Static `public/sitemap.xml` includes all three intended indexable pages and excludes the error page. `robots.txt` allows crawling and references the correct sitemap. Public pages have no noindex. Error page has no explicit noindex: add it through an optional layout prop. Live HTTP status, redirects, response headers and Google-selected canonicals need deployment verification.
6. **Structured data (low).** Existing public pages contain WebPage markup. Add a visible breadcrumb to the reference and matching BreadcrumbList/WebPage graph. Do not promise rich results. Homepage FAQ markup is not evidence of Google FAQ rich-result eligibility.
7. **Mobile and semantics.** Existing layout uses breakpoint-specific tables, labeled inputs, focus states, skip link, semantic sections and reduced-motion support. Preserve these. New controls must be responsive, labeled, keyboard usable, expose validation/status, and leave all values accessible without JavaScript. Verify rendered overflow and interactions locally. Preserve full chart in print even when filtering.

## Duplication and search evidence limits

Homepage and chart intentionally share mathematical reference data but serve calculator and printable lookup tasks respectively. Keep their self-canonicals and strengthen the reference page's purpose; no measured cannibalization can be concluded without query-by-page exports. No exports were attached. Google positions 34–39, Bing 4–6 and score-query visibility are user-supplied context, not independently verified metrics or a diagnosis. Do not infer a ranking cause or forecast gains.
